git stash и git commit
git stash
git stash временно сохраняет незакоммиченные изменения и очищает рабочую директорию.
Я использую его, когда не закончил работу, но мне нужно переключиться на другую ветку или сначала подтянуть изменения.
От git commit отличается тем, что stash не добавляет обычный коммит в историю. Он просто временно убирает мои изменения, чтобы потом я мог их вернуть.
Я использовал:

git stash
git stash list
git stash pop
git commit
git commit сохраняет мои изменения в истории Git.
Я использую его, когда закончил какую-то часть работы и хочу сохранить её как отдельный этап.

Пример:
git add .
git commit -m "Добавил изменения"
git merge и git rebase
git merge
git merge нужен, чтобы объединить изменения из одной ветки с другой.

Например, я работал в своей ветке и закончил работу, после чего хочу добавить её изменения в main.

git switch main
git merge feature
git rebase

git rebase нужен, чтобы взять мои коммиты и поставить их поверх последних изменений другой ветки.

Я использую его, когда хочу обновить свою ветку изменениями из main.

git switch feature
git rebase main

Главное отличие в том, что merge просто объединяет ветки, а rebase переносит мои коммиты на новую основу и меняет историю.

git reset и git revert
git reset
git reset можно использовать, чтобы отменить коммит и вернуться назад по истории.

Например:

git reset --soft HEAD~1
Я бы использовал его, если случайно сделал коммит и хочу его убрать, но оставить изменения.
git revert
git revert тоже отменяет изменения коммита, но делает для этого новый коммит.
git revert HEAD

Главное отличие: reset меняет историю, а revert оставляет старую историю и добавляет новый коммит, который отменяет изменения.

git fetch и git pull
git fetch

git fetch скачивает информацию о новых изменениях с GitHub, но саму мою текущую ветку не меняет.

git fetch origin

Я использую его, когда хочу сначала посмотреть, что изменилось на GitHub.
git pull
git pull сразу получает изменения с GitHub и добавляет их в мою текущую ветку.
git pull origin main

Получается:
git fetch = просто получить изменения
git pull = получить и применить изменения
git restore и git checkout
git restore
git restore использую, когда хочу вернуть файл обратно или убрать его из staging.
Например:
git restore file.txt
Или:
git restore --staged file.txt
git checkout
git checkout раньше использовался для разных вещей, например для переключения веток.
git checkout main

Сейчас для переключения веток удобнее использовать:
git switch main

А для файлов:
git restore file.txt
То есть сейчас switch больше используется для веток, а restore для файлов.
